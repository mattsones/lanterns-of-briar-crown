## Save Boundary

`SavePayload.chapter5` is a typed, version-1 block owned by `src/game/chapter5Runtime.ts`. It stores node and pending view, awareness, personnel and tools, panes, invalid history, resolved checks, frozen boss profile, pending combat, carriage step, and the once-only recovery/progression benefits. Each interaction writes state and current party resources together through the existing checkpoint path; manual slots and disk exports carry the same block.

The schematic's logical node is stored separately from the existing parent Relay region/position. This keeps the small spike independent of the seven full Chapter 5 production-map registrations. A reload reopens an unfinished interaction or offers **Resume the confrontation** from its pre-combat resource snapshot. Ordinary combat retry semantics remain in place.

An older save with no Chapter 5 block begins unstarted. Partial v1 fields take unearned defaults; malformed types, unsupported versions, invalid panes/checks, and contradictory rescue phases reject the save. Migration never invents completed infiltration or a rescue.
